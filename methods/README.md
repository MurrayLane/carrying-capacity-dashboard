# Method modules

A method module is one change to the model's method, kept apart from the data it is applied to. A release names the modules it uses (`"methods": ["recycling-stage"]` in its
`release.json`); the builder applies them, in order, on top of the workbook (and any cell overrides) of the release's data set. The same module therefore works on the 2011 data
and on the 2025 data, which is what separates the effect of the data from the effect of the method in the comparison (`results/comparison_cells.csv`).

```
methods/<id>/method.json
  id, label, description
  line           "improved" (line 2 of the two lines of enquiry); the thesis method is the unmodified workbook and needs no module
  cellOverrides  { sheet: { A1: value or "=formula" } }   cells to replace or add, only the module's own
  patches        [ { preset, field, value, reason } ]    defaults the module needs (for example the recycling setting)
  errata         [ text ]                                  what the module does not fix or assumes
```

Rules

1. **A module holds only its own cells.** Modules must not overlap cells; the resolver applies them in the order of the release's list, and a later one wins.
2. **A module is data-free.** Anything computed from a vintage of data (a resilience table from the series to 2024, a yield matrix) belongs to a data layer or an alternate release, not to a module. `2025-resilience-loo` is such an alternate.
3. **A release locks its modules.** `inputFiles` includes each module's `method.json`, so a frozen release is hash-checked against them; correct a module by making a new one.
4. **Modules are generated by their analysis scripts**, which are the record of how they were made; do not edit them by hand.

| Module | What it changes | Script | Write-up |
|---|---|---|---|
| `reserve-pro-rata` | Settings!C55:E55: a shortfall of reserve and infrastructure land is shared by cropping, pasture and non-agricultural land in proportion to their areas (SCOPE E13) | `analysis/long_term_2025/make_release_reserve.py` | `analysis/long_term_2025/README.md` |
| `recycling-stage` | Settings!BK1:BR40 (new tables), Base!P (275 formulas), Recycle!F2:F8: recycling split by stage, origin, dry matter and the law in force, with uptake by stage (SCOPE E4, E15) | `analysis/waste_2025/recycling_stages.mjs release` | `analysis/waste_2025/README_stages.md` |

The improved method of the comparison is the list `IMPROVED` in `analysis/comparison_2025/make_cells.py`.

## The four cells of the comparison

| | thesis method (line 1) | improved method (line 2) |
|---|---|---|
| **2011 data** | `2011-corrected` (the default release; `2011` is the site as published) | `2011-improved` |
| **2025 data** | `2025-mirror` (the tip of the data chain, identical to `2025-fuel`) | `2025-improved` |

`results/comparison_cells.csv` has, for every zone and both presets, the capacity in each cell, the **data effect** (2025 against 2011 on the thesis method), the **method effect** on each
vintage and their **interaction**; the three add up to the total change from `2011-corrected` to `2025-improved`.
