# Builder brief B86: the provenance map tool (decision 78)

Rules: plain language; no time words; no em dashes. No git; no subagents; no network. Write only `qa/tools/make_provenance.py`, `qa/provenance_A.md`, `qa/provenance_B.md` and `qa/reports/B86_provenance_map_tool.md`.

Build a script that, from `papers/A_results/SECTION_SCOPE.md` and `papers/B_methods/SECTION_SCOPE.md` (the evidence and sources tables of each section block), `qa/claims_register.csv`, `qa/sources_register.csv` and `qa/literature_register.csv`, writes one Markdown map per paper: for each section, for each point, a row per fact: fact (the scope's text fragment or claim statement, shortened) → claim id, tier, status → output file and locator → script → data source ids with their kind and status → original source (origin field) → literature ids with read status. Each link shows its status in one word (two-route / one-route / none; source verified / unverified; literature page-level / read / weak), and the map ends with per-section and per-paper tallies and a list of every broken link (a claim id the scope cites that the register lacks; a source id a claim names that the register lacks; a file path that does not exist; a literature id with no file). The script must be rerunnable (`python3 qa/tools/make_provenance.py`) and deterministic. Keep the parsing tolerant of the scopes' table formats; where a point's evidence cannot be parsed, list it under "unparsed" rather than dropping it.

Report: how the parser reads the scopes, the tallies for both papers, the broken links found, and "Wrong-value check:" with one deliberate example of a link the script would wrongly mark (and why it does not), marked as an example.
