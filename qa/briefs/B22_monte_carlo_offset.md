# Builder brief B22: fix the Monte Carlo group-factor offset (defect X054)

Rules: edit only `analysis/sensitivity_2025/monte_carlo.mjs` and `analysis/sensitivity_2025/README.md` (a note under the Monte Carlo heading); working files in your scratch folder /tmp/claude-0/-home-user/31136410-cd0a-5a0c-99b8-c10608414678/scratchpad/b22; do not write to `results/` or `web/public/data/`; no git; no subagents; network only if step 1 needs the ABS files and `analysis/recent_data/fetch_recent.py` can get them; plain language; no time words.

**The fault (V08 checker, `qa/reports/V08_regional_flips.md`, part D).** `monte_carlo.mjs` applies the field-crop and vegetable/fruit/nut group factors as `Math.abs(s) * (variant matrix - base matrix)`, with the variant matrices `gt_field_lo`, `gt_field_hi`, `gt_hort_lo`, `gt_hort_hi` written by `build_variants.py` into a work folder that is not in the repository. Those matrices carry a constant offset from the current `data/2025/yield_matrix_livestock.csv`, so a factor of -1 and of +1 move capacity the same way (Rangelands WA short term -8.2% at both ends; the offset exceeds 1% in 57 of 120 zone-presets for field crops and 70 of 120 for horticulture; Australia long term about +4.6% for each factor). The one-at-a-time file `oat_2025-fixed_all.csv` shows it.

1. **Find the work folder.** Look for the folder `monte_carlo.mjs` was last run with (the README of the folder, `monte_carlo.md`, the draws files' headers, HANDOFF.md). If it exists on this machine, compare its `gt_field_lo` and `gt_field_hi` matrices with the current base matrix row by row and report the offset: which rows, which zones, and what the matrices were built on (the crop years, the livestock calibration, the base release). If it does not exist, say so.
2. **Fix.** Preferred: rebuild the four group-factor variants on the current base by running the relevant `yield_variant` calls of `build_variants.py` (only those four; check what `zone_yields.py` and `livestock_zone.py` need, and whether the ABS files are on hand under `data/` or must be fetched). If the rebuild cannot be done, change `monte_carlo.mjs` so that each factor's yield difference is the sign-symmetric half-difference, `s * (hi - lo) / 2`, which removes a constant offset, and state in the README note that this is the linear shortcut and why. In either case the meat-window differences must be checked for the same offset and treated the same way.
3. **Prove it.** With the fix, run the one-at-a-time corners for the two factors on `2025-fixed` (the way `oat_2025-fixed_all.csv` was made; find the command) into your scratch folder and show that -1 and +1 now move capacity in opposite directions by about equal amounts, for Australia, Rangelands WA, Western NSW and three other zones, both presets. Then run 200 draws on `2025-fixed` into your scratch folder (not `results/`) and report the national p5 and p95, short and long term, against the committed 35.9 to 45.1 and 14.3 to 17.8, and whether any zone's base now lies outside its own range.
4. **Report**: the cause, the fix, the proof, the trial ranges, and the exact commands for the full rerun of the three releases (2025-fixed, 2025-mirror, 2025-improved, 1,000 draws, all zones) and for the quick range, so the coordinator can run them on Murray's decision. Do not run the full rerun.
